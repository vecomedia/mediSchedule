## Project: MediSchedule

A **learning project** — a medical appointment scheduling app built with Next.js 16 + React 19 + TypeScript + Tailwind CSS 4. No real database; all data is generated by `@faker-js/faker` (seeded, deterministic).

### Stack

| Layer | Choice |
|---|---|
| Framework | Next.js 16 (App Router) |
| UI | React 19, Tailwind CSS 4 |
| Auth | NextAuth.js v5 beta (`next-auth@5.0.0-beta.31`) |
| Data | `@faker-js/faker` — no DB (yet) |
| Forms | `react-hook-form` + `@hookform/resolvers` + Zod |
| Icons | `lucide-react` |

### Commands

```bash
npm run dev     # start dev server (port 3000)
npm run build   # production build
npm run lint    # eslint
```

### Route Architecture

```
src/app/
  (auth)/login/        # public — login page
  (app)/               # protected by middleware
    layout.tsx         # sidebar nav
    dashboard/
    appointments/
    patients/
  design-system/       # component showcase
  api/auth/[...nextauth]/
```

Route group `(app)` is protected via `src/middleware.ts` — all routes except `/login` redirect unauthenticated users.

### Data Layer

- **Types**: `src/lib/types.ts` — `Patient`, `Doctor`, `Appointment`, `AppointmentDetails`, `AuthUser`
- **Seed data**: `src/lib/faker-data.ts` — `faker.seed(42)`, 20 patients, 8 doctors, 50 appointments
- **Query functions**: `src/lib/data.ts` — `getPatients()`, `getDoctors()`, `getAppointments()`, `getAppointmentById()` — swap these for Prisma later without changing types

### UI Components

`shadcn/ui` is **NOT used**. All components are hand-built in `src/app/components/ui/`:
`button.tsx`, `input.tsx`, `label.tsx`, `card.tsx`, `badge.tsx`

Color palette (Tailwind): `blue-600` primary · `emerald-*` success · `amber-*` warning · `slate-*` neutral

Design reference: `src/app/components/DesignSystem.tsx` — view at `/design-system`

### Auth

- Provider: `CredentialsProvider` via `src/auth.ts`
- Test users: `admin@medi.dev / password123` · `reception@medi.dev / password123`
- Roles: `admin` | `receptionist`
- Session token extended with `id` and `role` — access via `auth()` in Server Components or `useSession()` in Client Components

### Key Conventions

- **Server Components by default** — add `"use client"` only when using hooks or browser APIs
- Form validation with Zod schemas in `src/lib/validations/`
- `AppointmentDetails` (hydrated) vs `Appointment` (raw) — use `getAppointmentById()` when you need patient/doctor joined data
- Do **not** install shadcn — the point is learning to build components
